# AIVideo 双链启动（Ubuntu Fabric + Windows）

| 运行位置 | 服务 | 默认地址 |
| --- | --- | --- |
| Ubuntu 服务器 | Fabric、Fabric CA、Node.js 存证网关 | 网关监听 `127.0.0.1:8801` |
| Windows | Ganache 测试 VCR 积分链 | `http://127.0.0.1:8545` |
| Windows | SSH 隧道 | Windows 的 `127.0.0.1:8801` 转发到 Ubuntu 网关 |
| Windows | Python 后端、Flutter 网页 | 后端 `8000`，网页 `8080` |

**当前已有 Ubuntu Fabric 网络的升级顺序**是先升级 Ubuntu 链码和网关，再启动 Windows 隧道、后端和新版网页。链码已部署 `3.1` 且网关文件已更新时，从第 2 节启动网关。首次搭建 Ubuntu 测试网时，先完成第 5 节。

示例已填入当前 Ubuntu SSH 地址 `root@fabric.example.com` 和端口 `22`。更换服务器时修改引号内的登录地址。若使用其他账号，把 Windows 命令里的 `/root` 换成该账号的家目录。

## 1. 升级 Ubuntu 上的 video-evidence 链码

在 **Windows PowerShell** 上传新版链码和网关。若 SSH 使用自定义端口，将这里的 `22` 改为实际端口。

```powershell
$fabricServer = 'root@fabric.example.com'
$fabricSshPort = 22
scp.exe -P $fabricSshPort 'G:\AIVideo\双链存证\chaincode\video-evidence\lib\videoEvidence.js' "${fabricServer}:/root/aivideo-fabric/chaincode/video-evidence/lib/videoEvidence.js"
if ($LASTEXITCODE -ne 0) { throw '链码上传失败，请检查 scp 的原始报错' }
scp.exe -P $fabricSshPort 'G:\AIVideo\双链存证\bridge\server.js' "${fabricServer}:/root/aivideo-fabric/bridge/server.js"
if ($LASTEXITCODE -ne 0) { throw '网关脚本上传失败，请检查 scp 的原始报错' }
```

在 **Ubuntu SSH 窗口**查当前链码版本和序号。

```bash
(
  set -e
  cd "$HOME/fabric-samples/test-network"
  export PATH="$PWD/../bin:$PATH"
  export FABRIC_CFG_PATH="$PWD/../config"
  export TEST_NETWORK_HOME="$PWD"
  unset OVERRIDE_ORG
  . scripts/envVar.sh
  setGlobals 1
  peer lifecycle chaincode querycommitted -C videochannel -n video-evidence
)
```

当前服务器已提交的链码是 `Version: 1.0, Sequence: 2`。执行以下命令升级到版本 `3.1`、序号 `3`。如果查询结果是其他序号，`-ccs` 填账本上的当前序号加一。若已成功部署 `3.1`，接着启动网关。升级复用现有 `videochannel`、登记证书和账本。Org1 和 Org2 应在线，链码部署和存证写入需要两个组织参与。

```bash
cd "$HOME/fabric-samples/test-network"
unset OVERRIDE_ORG
./network.sh deployCC -c videochannel -ccn video-evidence -ccp "$HOME/aivideo-fabric/chaincode/video-evidence" -ccl javascript -ccv 3.1 -ccs 3 -ccep "AND('Org1MSP.peer','Org2MSP.peer')"
```

看到 `Chaincode definition committed on channel 'videochannel'`，且两个组织查到预期版本和序号，即完成升级。 [Fabric 链码升级说明](https://hyperledger-fabric.readthedocs.io/en/release-2.5/chaincode_lifecycle.html#upgrade-a-chaincode)

## 2. 在 Ubuntu 启动存证网关

如果旧网关还在运行，在它的 **Ubuntu SSH 窗口**按 `Ctrl+C`，再执行下面这段。已运行的账本继续复用 `~/aivideo-fabric/config` 中的网络标识、网关口令和已签发的 `aivideo-recorder` 证书。

如果这是第 5 节刚创建的新账本，先按第 5 节签发证书并生成配置，再在本段取消 `node server.js --initialize` 前的注释，执行首次初始化。

```bash
(
  set -e
  if [ -s "$HOME/.nvm/nvm.sh" ]; then
    . "$HOME/.nvm/nvm.sh"
    nvm use 24
  else
    export PATH="$HOME/.local/node-v24.22.3-linux-x64/bin:$PATH"
  fi
  node -v
  export FABRIC_SAMPLES_DIR="$HOME/fabric-samples"
  export USER_MSP_PATH="$FABRIC_SAMPLES_DIR/test-network/organizations/peerOrganizations/org1.example.com/users/aivideo-recorder/msp"
  export CERT_PATH="$USER_MSP_PATH/signcerts/cert.pem"
  test -s "$CERT_PATH"
  FABRIC_NETWORK_ID=$(cat "$HOME/aivideo-fabric/config/fabric-network.txt")
  FABRIC_BRIDGE_TOKEN=$(cat "$HOME/aivideo-fabric/config/fabric-token.key")
  export FABRIC_NETWORK_ID FABRIC_BRIDGE_TOKEN
  export PORT=8801

  cd "$HOME/aivideo-fabric/bridge"
  if [ ! -d node_modules ]; then npm ci; fi
  node -e 'require("@hyperledger/fabric-gateway"); console.log("Fabric Gateway SDK OK", process.version)'
  # node server.js --initialize
  npm start
)
```

看到 `Fabric Gateway bridge 监听 http://127.0.0.1:8801` 后保持窗口开着。另开一个 **Ubuntu SSH 窗口**执行以下两条。第二条读到 `channel: videochannel`、`chaincode: video-evidence` 和 `schemaVersion: 3`，说明网关已能回读当前账本。

```bash
curl -fsS http://127.0.0.1:8801/health
curl -fsS -H "Authorization: Bearer $(cat "$HOME/aivideo-fabric/config/fabric-token.key")" \
  http://127.0.0.1:8801/v1/registry
```

## 3. 在 Windows 启动 Ganache、隧道、后端和网页

首次使用 Windows 应用需要后端 `.venv`、Flutter SDK，以及 `双链存证` 下已安装的 npm 依赖。已有 Ganache 和 SSH 隧道在运行时，可直接更新后端和网页。替换旧进程时，在旧后端和旧网页窗口分别按 `Ctrl+C` 释放 `8000`、`8080`。

### 窗口 1 运行 Ganache

```powershell
Set-Location 'G:\AIVideo'
.\上线本地\start-ganache.ps1
```

### 窗口 2 运行 SSH 隧道

登录后窗口会保持安静。测试网关返回 `{"ok":true}` 后，用下一窗口启动后端。

```powershell
$fabricServer = 'root@fabric.example.com'
$fabricSshPort = 22
ssh -p $fabricSshPort -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8801:127.0.0.1:8801 $fabricServer
```

在其他 Windows 窗口检查隧道。

```powershell
curl.exe --noproxy 127.0.0.1 --max-time 5 -fsS http://127.0.0.1:8801/health
```

### 窗口 3 读取 Ubuntu 配置并运行后端

以下命令按 Ubuntu 用 `root` 登录及安装路径 `/root/aivideo-fabric` 编写。它从 SSH 读取配置，验证链上登记信息，再用 `-Fabric` 启动。后端启动脚本会对现有演示库执行 Alembic 迁移。

```powershell
& {
    $ErrorActionPreference = 'Stop'
    Set-Location 'G:\AIVideo'
    $fabricServer = 'root@fabric.example.com'
    $fabricSshPort = 22
    $fabricConfig = @(ssh -p $fabricSshPort $fabricServer 'cat /root/aivideo-fabric/config/fabric-network.txt /root/aivideo-fabric/config/fabric-token.key')
    if ($LASTEXITCODE -ne 0 -or $fabricConfig.Count -ne 2) {
        throw '读取 Fabric 配置失败，请检查 SSH 或 cat 的原始报错'
    }

    $env:FABRIC_NETWORK_ID = $fabricConfig[0].Trim()
    $env:FABRIC_BRIDGE_TOKEN = $fabricConfig[1].Trim()
    $env:FABRIC_BRIDGE_URL = 'http://127.0.0.1:8801'
    $registry = Invoke-RestMethod "$env:FABRIC_BRIDGE_URL/v1/registry" -Headers @{
        Authorization = "Bearer $env:FABRIC_BRIDGE_TOKEN"
    }
    if ($registry.networkId -ne $env:FABRIC_NETWORK_ID -or
        $registry.channel -ne 'videochannel' -or
        $registry.chaincode -ne 'video-evidence' -or
        $registry.schemaVersion -ne 3) {
        throw '网关返回的登记信息与配置不一致'
    }
    $registry
    .\上线本地\start-backend.ps1 -Fabric
}
```

看到 `Uvicorn running on http://127.0.0.1:8000` 表示后端已开始监听。如果报 `10048`，先检查 `8000` 的监听进程。

### 窗口 4 构建并运行新版网页

```powershell
Set-Location 'G:\AIVideo'
.\上线本地\start-web.ps1 -Rebuild
```

打开 `http://127.0.0.1:8080`。若要让其他设备打开分享链接，把 Web 产物部署到访客能访问的地址，构建时将 `API_BASE_URL` 指向访客能访问的后端。

## 4. 验收公开核验和作品交易

1. 生成一条新视频并等待「已存证」。作品页显示存证编号、Fabric 交易 ID 和 SHA-256。下载原片后可用 `Get-FileHash -Algorithm SHA256` 核对文件指纹。
2. 作者 A 点「公开存证」，填写标题、显示名和作品介绍，并勾选是否公开原提示词。在无痕窗口打开核验链接，验证访客可以查到回执和已授权公开的资料。撤销公开后，重新访问原链接应显示「未找到公开记录」。
3. A 在「我的 → 作品交易中心 → 我的持有」以 50 VCR 上架，可指定 B。B 确认购买后核对 B 扣 50、A 加 50。B 可下载原片或再次上架，原始作者显示为 A。
4. 在「成交记录」刷新，看到「已上链」和 Fabric 交易 ID。重新加载公开核验页应看到转让回执。若验证掉线恢复，可以在成交前暂时关闭 Windows 隧道，成交先显示「待上链」，恢复隧道后等待自动确认，再核对双方流水和链上回执。

有成交编号后，可在 **Ubuntu SSH 窗口**读取 Fabric 回执。把 `成交编号` 换成成交页里的编号。

```bash
curl -fsS -H "Authorization: Bearer $(cat "$HOME/aivideo-fabric/config/fabric-token.key")" \
  http://127.0.0.1:8801/v1/trades/成交编号
```

也可在 Windows 执行原有积分与视频存证验收脚本。它会在演示账套注册测试账号并生成测试作品。

```powershell
Set-Location 'G:\AIVideo'
$env:INVITE_CODE = 'AIVIDEO-DEMO'
$env:REQUIRE_FABRIC = '1'
.\backend\.venv\Scripts\python.exe .\上线本地\accept_credits.py
```

## 5. 首次在 Ubuntu 上部署 Fabric

在 Ubuntu 准备 Docker、Docker Compose、`jq`、Fabric `2.5.16` 示例与命令行工具、Fabric CA `1.5.15` 和 Node.js 24。示例目录使用 `~/fabric-samples`。 [Fabric 工具和镜像安装](https://hyperledger-fabric.readthedocs.io/en/release-2.5/install.html)

在 **Windows PowerShell** 打包链码和网关源码并上传。

```powershell
$fabricServer = 'root@fabric.example.com'
$fabricSshPort = 22
$fabricArchive = Join-Path $env:TEMP 'aivideo-fabric-source.tar.gz'
$fabricFiles = @(
    'chaincode/video-evidence/index.js'
    'chaincode/video-evidence/package.json'
    'chaincode/video-evidence/package-lock.json'
    'chaincode/video-evidence/lib'
    'bridge/server.js'
    'bridge/package.json'
    'bridge/package-lock.json'
)
tar.exe -czf $fabricArchive -C 'G:\AIVideo\双链存证' @fabricFiles
if ($LASTEXITCODE -ne 0) { throw '打包失败' }
scp.exe -P $fabricSshPort $fabricArchive "${fabricServer}:/root/aivideo-fabric-source.tar.gz"
if ($LASTEXITCODE -ne 0) { throw '上传失败，请检查 scp 的原始报错' }
```

在 **Ubuntu** 解压、创建通道并部署 `3.1`。新通道上的首个链码定义使用序号 `1`。

```bash
(
  set -e
  mkdir -p "$HOME/aivideo-fabric"
  tar -xzf "$HOME/aivideo-fabric-source.tar.gz" -C "$HOME/aivideo-fabric"
  cd "$HOME/fabric-samples/test-network"
  unset OVERRIDE_ORG
  docker tag hyperledger/fabric-peer:2.5.16 hyperledger/fabric-peer:latest
  docker tag hyperledger/fabric-ca:1.5.15 hyperledger/fabric-ca:latest
  sed -i \
    -e 's|hyperledger/fabric-peer:latest|hyperledger/fabric-peer:2.5.16|g' \
    -e 's|hyperledger/fabric-orderer:latest|hyperledger/fabric-orderer:2.5.16|g' \
    -e 's|hyperledger/fabric-ca:latest|hyperledger/fabric-ca:1.5.15|g' \
    compose/compose-test-net.yaml \
    compose/docker/docker-compose-test-net.yaml \
    compose/compose-ca.yaml
  ./network.sh up createChannel -ca -c videochannel -i 2.5.16 -cai 1.5.15
  ./network.sh deployCC -c videochannel -ccn video-evidence -ccp "$HOME/aivideo-fabric/chaincode/video-evidence" -ccl javascript -ccv 3.1 -ccs 1 -ccep "AND('Org1MSP.peer','Org2MSP.peer')"
)
```

在新 CA 上第一次注册 `aivideo-recorder` 并签发登记证书。若这是重建的新账本，先备份重建前的 `~/aivideo-fabric/config`，再生成本次账本配置。 [Fabric CA 注册与证书属性](https://hyperledger-fabric-ca.readthedocs.io/en/latest/users-guide.html)

```bash
(
  set -e
  umask 077
  export PATH="$HOME/fabric-samples/bin:$PATH"
  cd "$HOME/fabric-samples/test-network"
  org1="$PWD/organizations/peerOrganizations/org1.example.com"
  ca_pem="$PWD/organizations/fabric-ca/org1/ca-cert.pem"
  export FABRIC_CA_CLIENT_HOME="$org1"
  recorder_secret=$(openssl rand -hex 24)
  fabric-ca-client register --caname ca-org1 --id.name aivideo-recorder \
    --id.secret "$recorder_secret" --id.type client --id.affiliation org1.department1 \
    --id.attrs 'evidence.role=recorder:ecert' --tls.certfiles "$ca_pem"
  fabric-ca-client enroll -u "https://aivideo-recorder:$recorder_secret@localhost:7054" \
    --caname ca-org1 -M "$org1/users/aivideo-recorder/msp" \
    --enrollment.attrs 'evidence.role' --tls.certfiles "$ca_pem"
  unset recorder_secret

  config_dir="$HOME/aivideo-fabric/config"
  mkdir -p "$config_dir"
  [ -s "$config_dir/fabric-network.txt" ] || openssl rand -hex 16 > "$config_dir/fabric-network.txt"
  [ -s "$config_dir/fabric-token.key" ] || openssl rand -hex 32 > "$config_dir/fabric-token.key"
)
```

完成后返回第 2 节，启用 `node server.js --initialize` 并启动网关。日常重启复用这两份配置文件。

## Ganache 测试账套切换

如确需更换当前测试账套的 VCR 合约，先停 Windows 后端，在指向相同演示数据库和 Ganache 的环境里运行 `python scripts/setup_chain.py --dry-run`。核对站内余额汇总后，用 `python scripts/setup_chain.py --new-deployment` 为当前账套创建新合约的期初记录。脚本会保留旧回执并归档旧队列。
