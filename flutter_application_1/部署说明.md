# 部署说明 · 前端上宝塔面板

> 打包和铺文件都有脚本（`scripts/build-web.sh`、`scripts/deploy-web.sh`）。
> 这一页只写**脚本碰不到、必须在面板上点**的那几步 —— 照着点一遍就完了。

---

## 一次性准备（每个服务器只做一次）

### 1. 建站点

宝塔 → **网站** → 添加站点：

| 字段 | 填什么 |
|---|---|
| 域名 | `你的服务器IP:端口`，比如 `fabric.example.com:37738` |
| 根目录 | 默认的 `/www/wwwroot/xxx` 就行（部署脚本会自己找到它） |
| FTP / 数据库 | 都**不创建** |
| PHP 版本 | 选「**纯静态**」 |

> ⚠️ **端口不要用宝塔面板自己的那个**（面板占用的端口再建站点会让面板打不开）。另开一个，比如面板在 37737，站点就用 37738。

### 2. 放行端口（**最容易漏的一步**）

两处都要放行，只放一处就是「一直转圈、连不上」：

1. 宝塔 → **安全** → 添加端口规则，放行上面那个端口
2. **云厂商控制台 → 安全组** → 加一条入方向规则，放行同一个端口

### 3. 开 SSL（**必做，不是可选项**）

宝塔 → 网站 → 点这个站点 → **设置** → **SSL**：

* **有域名** → Let's Encrypt，一键签发，然后打开「**强制 HTTPS**」
* **只有 IP** → Let's Encrypt 签不了 IP，选「**自签证书**」；浏览器第一次会弹安全警告，点「继续前往」就能用

**为什么非做不可**（已在真实浏览器上实测，不是推测）：

```
http://真实IP    →  isSecureContext = false,  crypto.subtle = undefined
```

Web 上 token 存在 `flutter_secure_storage` 里，它要用浏览器的 WebCrypto；浏览器只在**安全上下文**（`https://`、`http://localhost`、`http://127.0.0.1`）里才提供这个 API。于是普通 http 上的表现是：**注册/登录按钮一直转圈，界面上没有任何提示**——异常根本没回到 Dart 层，App 自己都不知道出事了。

换句话说：**http 上不是「不能打开」，是「不能登录」**，而且症状极难判断，很容易被当成「卡住了」或者「后端没通」。

## 每次发版（两条命令）

### 本机打包

```bash
cd G:\AIVideo\flutter_application_1
bash scripts/build-web.sh                    # 演示版（Mock）
bash scripts/build-web.sh --skip-build       # 只重新打包，不重新构建
```

要接真后端（**后端还不存在，现在填不出地址**）：

```bash
bash scripts/build-web.sh --mode real --api-base-url https://api.你的域名
```

产物在 `dist/aivideo-web-<模式>-<时间戳>.zip`，里面是：

```
web/                ← 网站文件（脚本会自动识别这一层，不用你操心多没多一层目录）
deploy-web.sh       ← 部署脚本
BUILD-INFO.txt      ← 打包时间、git commit、模式、main.dart.js 的 sha256
```

### 传到服务器并部署

**方式 A（用面板，不碰命令行）**

1. 宝塔 → **文件** → 进 `/root` → **上传**那个 zip
2. 宝塔 → **终端** → 粘这三行：

```bash
cd /root
unzip -o aivideo-web-mock-<时间戳>.zip -d aivideo-deploy
bash aivideo-deploy/deploy-web.sh
```

**方式 B（本机 scp，更省事）**

```bash
scp dist/aivideo-web-mock-<时间戳>.zip root@你的服务器IP:/root/
```

然后 SSH 上去跑上面那三行。

### 先看看它打算干什么（不写文件）

```bash
bash aivideo-deploy/deploy-web.sh --dry-run
```

### 部署脚本会做/不会做的事

**会做**：找站点根目录（找不到会停下来问你，不猜）、体检文件完整性（**缺 `canvaskit/` 这类直接停，不做半成品部署**）、只清理上一版的 Flutter 产物（**不动 `.user.ini` 和你自己放的东西**）、修权限属主。

**不会做**：建站点、放行端口、签证书 —— 就是上面「一次性准备」那三步，得你在面板上点。

**可选**：`--patch-nginx` 会往站点配置里加两条「版本入口不缓存」的规则（先备份、`nginx -t` 过了才 reload，测不过自动还原）。不加也能跑，只是以后你更新版本时老用户可能还看到旧的。注意：之后你在面板里改这个站点的设置，面板可能重写配置把这它覆盖掉。

## 出问题了怎么查

| 症状 | 先查什么 |
|---|---|
| **白屏** | F12 → Console，看 404 的是哪个文件。多半是 `canvaskit/` 或 `assets/` 没上去（部署脚本第 2 步会拦，所以真出现说明包本身有问题：重新打包） |
| **一直转圈 / 连不上** | 端口没放行。宝塔「安全」和云厂商「安全组」**两处都要开** |
| **登录注册一直转圈** | **https 没配**。这不是 App 的问题，见上面第 3 节 |
| **改了代码但界面没变** | 浏览器缓存，Ctrl+Shift+R；长期方案是加 `--patch-nginx` |
| **页面能开但图全丢** | `assets/` 没传全，重新部署一次 |

## 现在这一版是什么

默认打出来的包是 **Mock 演示版**：不连后端，数据存在浏览器内存里 —— **刷新页面就会掉登录**，注册的账号也活不过一次刷新。给评审/内测看够用，但**还不能收真实用户**。

接真后端要等两件事：后端把 `HANDOFF.md` §5 那份契约缺口表对齐，以及 `DioApiClient`（一次都没跑过的那部分代码）在真实响应上核一遍。
