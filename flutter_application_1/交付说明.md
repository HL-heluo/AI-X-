## 1. 做完了什么（按你能感知的功能说）

### 1.1 主链路（这是产品的唯一主线）

> 首页写一句话 → 出图 → 结果页 → 做成视频 → 视频结果页

一路走通，**描述和参考图都会自动带过去**（不用重打一遍），
生成的图和视频上都有 **「AI 生成」标识**。

### 1.2 全部页面

| 页面 | 状态 |
|---|---|
| 启动页 / 登录页 / 注册页 | ✅ 冷启动先读 token 再决定去哪，不会闪一下登录页 |
| 首页（开始创作） | ✅ 真接服务端：报价、提交、进行中任务条、最近作品 |
| 图片生成 / 图片结果 | ✅ |
| 视频生成 / 视频结果 | ✅ 720P；结果页点播放才初始化播放器 |
| 作品（进行中 / 已完成） | ✅ 分段、网格、空态、AI 标识 |
| 任务详情 | ✅ 用 taskId 拉，排队位次是真的 |
| 我的 / 积分 / 设置 | ✅ 积分余额、流水（分页）、设置项、退出登录 |

### 1.3 看不见但很要紧的三件

* **轮询与退避**：进行中的任务 5 秒一拍，忙久了退到 15 秒；
  没任务时**心跳自己停**（登出也会停）。App 切到后台停、回前台立刻补一拍。
* **完成通知**：任务跑完发一条本地通知，**正文带上你自己的提示词**
  （同时跑了图和视频时，一眼知道是哪个）。
* **任务状态绝不进 App 内存**：所有任务数据都是现拉的，符合 §8.4 的硬规则。
  代价是每次进作品页都会有一次网络请求 —— 这是刻意的。

| # | 决定 | 为什么 |

## 4. 需要你拍板的

> **真正还要你回的只有 §4.2 / §4.3 / §4.4 三条。**
> §4.1 是**已经拍板闭环**的那条（注册赠送 20 → 50），留在这里是为了记录决策，

### 4.1 ✅ 已拍板：注册赠送 20 → 50（**这条已经闭掉了**）

原来这条写的是「新用户买不起任何一条视频，A/B/C 选一个」。你选了 **A**，
赠送额从 **20 提到 50**，并且改的是 **契约值**（§12.1 前后端一起改，已同步到文档）。
本节现在是**记录**，不是待办。

| | 改前 | 改后 |
|---|---|---|
| 注册赠送 | 20 | **50** |
| 一图（4）+ 一视频（冻结 32） | 36 > 20，**第一次就撞墙** | 36 ≤ 50，**跑得通** |
| 一图 + 一视频结算后余额 | — | 50 − 4 − 24 = **22** |
| 第二轮做视频（再冻 32） | — | 22 < 32，**仍然撞墙** |

**⚠️ 那条死路没有被解决，只是从「第一次」退到了「第二次」。**

很容易把这次改动读成「问题没了」，所以要说清楚它换来了什么、没换来什么：

* **换来了**：新用户能完整跑通一轮主线（注册 → 出图 → 转视频 → 播放）。
  这是真实的收益，也是选 A 的主要理由。
* **没换来**：第二轮做视频照样撞墙，而 v1 **仍然没有充值入口**（§7.6）。
  真正解决它的是 **v3 的充值** —— 这次没有、也不能解决那件事。

所以 §3.3 那条「不说请先充值」的守卫**必须原样保留**：余额不足时仍然要说清
差多少、为什么冻结比看到的多、并给一个「去看积分」的出口。
这次做的是**把撞墙的位置往后挪**，不是**把墙拆了**。

#### 「积分不足」的覆盖是**重建**的，不是删掉

这是这次改动最容易做错的地方。原来那条覆盖靠的是「注册送 20 < 冻结 32」这个
**数值关系**；赠送额一改，关系就没了 —— 如果把断言里的数字直接改掉，
`generation_flow_test.dart` 里那条用例会变成**永远通过的空壳**，
而上一轮花半批功夫修好的「假承诺」也就重新失去了守卫。

改成走**更长的那一档**：10 秒视频冻结 `(10 + 3) × 4 = 52 > 50`。
死路还在，只是退后了一步 —— **那条用例守的从来不是那个数字，
是「余额不足这条路径的界面还在、还说人话」**。

现在这条路径有**三处**守卫，都在跑：

| 测试 | 守的 |
|---|---|
| `fake_api_client_test.dart`「余额不足抛 INSUFFICIENT_CREDITS，且不留下任何痕迹」 | 被拒后余额/冻结/任务/流水**一个都不能动** |
| `repository_layer_test.dart`「积分不足时抛的是 INSUFFICIENT_CREDITS，UI 才能分支」 | 整条缝上传出来的确实是这个码 |
| `generation_flow_test.dart`「新用户选 10 秒视频」 | 界面说人话 + 给出路 + **这一屏不许出现「充值」** |

#### 顺带补的一个会撒谎的错误码

后端的 `INVITE_INVALID`（邀请码无效）在 §12.3 的表里没有，前端认不出，
注册页会说**「连不上服务器，检查一下网络再试」** —— 网络好得很，
错的是手里那个邀请码。这次一并补上了 `INVITE_INVALID` 并加了守卫测试
（`auth_flow_test.dart`「邀请码无效 → 说「邀请码无效」，不说「连不上服务器」」）。
这和上一轮修掉的「请先充值」是同一类：把用户支去解决一个不存在的问题。

### 4.2 `flutter build apk` 还是红的（**需要你动一下手**）

Windows 上 Kotlin 编译器守不住内存映射文件（`Could not close incremental caches`
→ `FilePageCache.registerPagedFileStorage` 断言失败）。**和代码无关**：
它打在该项目第一个被编译的 Kotlin 插件上。已试过全部无效：清 `build/`、
`./gradlew --stop`、关增量编译、改 in-process 编译策略。

还剩两步只有你能做（**我不敢按名字全杀 `java.exe`，怕连带干掉你开着的 IDE**）：

1. `tasklist | findstr java` 看两个残留的 Gradle/Kotlin 守护进程，杀掉对应 PID；
2. 给 Windows Defender 加排除项：`G:\AIVideo\flutter_application_1\build` 和 `~\.kotlin`
   —— 这是这个错误**最常见**的成因。

**这条不能一直红着**：`video_player`、本地通知都要真机验，Web 跑绿替代不了。

## 5. 我没做 / 做不到的（说清楚，不含糊）

### 5.1 真机（Android APK）一次都没跑过

原因就是 §4.2 那个工具链问题。**所有「真机才有的东西」因此都没验证**：
本地通知真的弹不弹、视频真的播放不播放、后台/前台切换的真实行为。
逻辑层面都有测试或 Mock 覆盖，但**真机行为属于未验证**。

### 5.2 `DioApiClient` 一次都没跑过

后端不存在，它没有对手可以打。所有对响应体形状的假设
（无信封、错误码在 `code` 字段）都集中在 `_decode` / `_toException` 两个方法里。
**接后端时先核这两个方法，不要改调用方。**

### 5.3 「重启仍保持登录」在浏览器里演不出来

不是坏了：Mock 把「token→用户」存在**进程内存**里，刷新页面等于重启进程，
Mock 忘了自己发过这个 token，于是 App **正确地**登出。
「写入/读回/解密」这半在真实浏览器里验过了（token 确实进了 `localStorage`
又能读回来），「恢复会话」那半由单元测试覆盖（同一个 Mock 跨两次容器存活）。
详见 `HANDOFF.md` §6。**要不要让 Mock 落盘由你定，我没顺手改。**

### 5.4 契约缺口 12 条

都记在 `HANDOFF.md` §5，是**接后端前必须和后端对齐**的东西
（401、用户名已占用、流水符号、`/tasks` 分页、3 秒余量怎么算……）。
这不是「没做完」，是**文档里真的没写**，App 侧只能先冻结一个合理的做法。
