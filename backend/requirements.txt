# ─────────────────────────────────────────────────────────────
# 后端依赖（工程文档 §4.1 的技术栈定稿）
#
# 【为什么 B0 就把**全部**依赖列出来装一遍，而不是用到才加】
# 这是从前端抄来的教训。§4.4 记着一条：前端历史上出现过 pub.dev 不通、
# 本地缓存里没有 `flutter_svg` 的情况，于是「必须在 C0 卡里一次性验证
# 四个新依赖可安装，装不上就立刻改设计，不能等写业务时才发现」。
#
# pip 这边同理，而且更糟 —— 想象一下 B5 写到一半，发现 `bcrypt` 装不上，
# 于是**密码哈希方案**要换。那不是一个包的替换，是一片已经写完的代码要改。
# 所以：**先证明全都装得上，再动第一行业务代码**（B0 的门禁就是这个）。
#
# 【每一条后面写清楚它为什么在这儿】不然半年后会有人问「这个包还有人用吗」，
# 然后删掉，然后某天线上炸了。
# ─────────────────────────────────────────────────────────────

# ── Web 框架 ──────────────────────────────────────────────
fastapi==0.115.6
    # §4.1 定稿。选它的实际理由：它的 `response_model` 会在**运行时**校验
    # 出参形状 —— 而本项目的整个前端契约就建立在「响应体形状必须精确」上
    # （无信封、available 不许出现、settled_amount 未结算必须是 null）。
    # 让框架替我们守住这些，比写 12 个端点的断言更省事，而且不会漏。
uvicorn[standard]==0.34.0
    # ASGI 服务器。`[standard]` 带上 uvloop/httptools/watchfiles ——
    # watchfiles 让 `--reload` 能用，开发期省事。
    # 【为什么不是 gunicorn】v1 是单机 + 单 worker（§8），不需要多进程管理。

# ── 数据库 ────────────────────────────────────────────────
sqlalchemy==2.0.36
    # §4.1：SQLAlchemy 2.0 风格（`Mapped[]` / `mapped_column`），
    # 不是 1.x 的 `Column(...)` 老写法。迁移到 PostgreSQL 时不用改模型。
alembic==1.14.0
    # 迁移。SQLite → PostgreSQL 这条路要靠它，手改表结构迟早出事。

# ── 配置与校验 ────────────────────────────────────────────
pydantic==2.10.4
pydantic-settings==2.7.0
    # 配置全部走环境变量（§4 铁律），这个包负责「从环境变量读 + 类型转换 +
    # 缺了就报错」。**它是密钥防线的一部分**：必填字段没默认值，
    # 忘了配 JWT_SECRET 会启动失败，而不是拿一个空字符串签发 token。
    # （默认值：pydantic 会被 fastapi 带进来，但显式列出来，
    #   免得哪天 fastapi 换了底层 pydantic 版本我们被打个措手不及。）

# ── HTTP 客户端（打即梦用）────────────────────────────────
httpx==0.28.1
    # §5：即梦是 REST + 签名头，不需要 SDK。选它而不是 requests 是因为
    # 它**同时**是异步的、且 `ASGITransport` 能让测试直接打 FastAPI app

# ── 鉴权 ──────────────────────────────────────────────────
bcrypt==4.2.1
    # §6.1 明确禁止明文密码。直接用它而不是 `passlib`：passlib 已经
    # 一年多没发版，且它和 bcrypt 4.x 的兼容问题在社区里反复出现
    # （会打印一行 "error reading bcrypt version" 然后照常工作）。
    # 这里是唯一用到哈希的地方，直接用底层库更省心。
pyjwt==2.10.1
    # JWT 签发与过期。§6.1 的会话方案：无 refresh token，过期即 401
    # 让前端登出（前端已经会处理，见 HANDOFF §5 第 1 条）。

python-multipart==0.0.20
    # FastAPI 的 `UploadFile` 依赖它。不装的话 `/uploads/image` 会报

pillow==11.1.0

# ── 对象存储（B6：S3 协议）────────────────────────────────
boto3==1.35.90
    # §9.1 的 `STORAGE=oss` 走 **S3 协议**，而不是某一家云的专有 SDK。
    #
    # 【为什么是这个选择】阿里云 OSS / 腾讯云 COS / MinIO / R2 说的是
    # 同一个协议，差别只有 `endpoint_url` 与寻址风格。换成专有 SDK 之后，
    # 「换个云厂商」就不再是一次配置改动，而是一次**代码改动 + 重新发版
    # + 重新验证** —— 而它们之间真正的差别其实只有那两个配置项。
    # （`Storage` 是个 Protocol，见 §12.2 的同款做法。）
    #
    # 【B0 时这里是「故意一条不列」】因为当时还没定用哪家，先装 SDK
    # 等于在没定的时候就把依赖焊死。B6 定了协议，于是现在能列出
    # 正确的那个包了。
    #
    # 【为什么固定到小版本】boto3 与 botocore 是一对，两个必须匹配。
    # 锁住它，免得某次 `pip install` 悄悄换到一个行为不同的版本上。
    # 它是**惰性 import** 的（`build_storage()` 里），所以 `STORAGE=local`
    # 的进程（包括每次 pytest）不为它付 import 时间。
