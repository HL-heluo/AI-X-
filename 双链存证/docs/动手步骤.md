# 亲手制作步骤（详细版）

> 面向：你自己一台 Windows 机器、`G:\AIVideo` 这套 Flutter + FastAPI 平台、一份课程报告。
> 原则：**先做能自己验证的，再做需要环境的。** 降级路线（G0→G1→G2）不需要 Docker，2~3 天能交出完整证据；
> Fabric 是可选升级项（+1~2 天），失败也不影响交作业。
>
> 每一步都写了：**命令 → 期望输出 → 验收标准 → 常见失败**。照着做，卡住时先看对应那一步的「失败处理」。

带着三个问题读 `VideoCredit.sol`：

1. 为什么是 `reserve` 而不是 `consume(user)`？（答案：`_spendAllowance` 要求用户先授权，平台拿不到没授权的钱）

3. `_update` 里的 `transferable=false` 拦住了什么？（答案：用户↔用户转账，只放行铸造/销毁/托管三向）

| 上传大视频很慢 | 本地节点只做分块存储，慢通常是磁盘；演示用几十 MB 以内 |

## 7. 附录 A：开发工具怎么选（Remix / Truffle / 本地脚本）

### 7.1 三个工具各自管什么

| 工具 | 是什么 | 在报告里的位置 | 本仓库对应物 |
| --- | --- | --- | --- |
| **Ganache** | 一条**本地以太坊链**（内存 EVM + JSON-RPC），默认 `127.0.0.1:8545`、chainId 1337 | 报告 2.2「开发环境使用私有链」；本地脚本证据的运行环境 | `npm test` 用**进程内** ganache（不用单独启动）；`deploy.js` / `demo_flow.js` 用**常驻** ganache（不需要钱包） |
| **Remix（在线）** | 浏览器里的**合约 IDE**：编辑 + 编译 + 部署 + 函数交互；自带 Remix VM 虚拟链 | 报告 2.2 的「编译与部署、交互验证」 | `remix/*.flat.sol`（已拍平、可直贴）+ `scripts/hash_inputs.js`（生成参数） |
| **Truffle** | 本地**工程框架**：编译 + migration 部署 + 测试 | 报告 2.2 的部署脚本与测试流程 | `scripts/compile.js` + `deploy.js` + `test.js`（自动化回归） |

一句话：**Ganache 是链，Remix 是 IDE，Truffle 是本地脚手架。** 链不能省，IDE 和脚手架可以任选。

### 7.2 推荐：用在线 Remix（不用 Truffle）

完整步骤（含截图清单、EVM 版本坑、常见报错）在 [`用Remix跑.md`](用Remix跑.md)。最短路径：

1. 打开 <https://remix.ethereum.org>，新建文件，粘贴 [`../remix/VideoCredit.flat.sol`](../remix/VideoCredit.flat.sol)；
2. Compiler 选 0.8.24~0.8.30，**EVM VERSION 选 `shanghai`**（不选的话部署到 Ganache 会 `invalid opcode`）；
3. Deploy & Run → Environment = **`Remix VM (Shanghai)`**（浏览器内虚拟链，自带 15 个各 100 ETH 的账户，**不需要钱包**）→ CONTRACT 选 `VideoCredit` → 构造参数填 `false` → Deploy；
4. 在函数面板里按顺序调 `mint` → `approve` → `reserve` → `settle`/`refund`，参数用 `node scripts/hash_inputs.js` 生成后照抄；
5. 存证部分同理，粘贴 [`../remix/VideoEvidence.flat.sol`](../remix/VideoEvidence.flat.sol)，调 `recordEvidence` / `verifyExact` / `verifyPerceptual`。

**为什么给的是 `.flat.sol`**：Remix 里 `import "@openzeppelin/..."` 会走 npm CDN，国内网络常拉不动；拍平文件把 OpenZeppelin 源码内联进来，**既不用联网拉依赖，也方便直接贴进报告附录**。这两个文件由 `node scripts/flatten.js` 生成，并已验证「拍平后编译出的字节码与 `artifacts/` 一致」。

**Remix 的边界**：适合交互验证与截图，**不能替代自动化测试**（没有版本化断言、不进 CI）。所以推荐组合：**Remix 做交互验证 + 本地 `npm test` 做回归**，两套证据都留。

## 9. 附录 C：报错索引

| 报错/现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| `Cannot find module 'solc' / 'ethers' / 'ganache'` | 依赖没装 | `cd G:\AIVideo\双链存证; npm install` |
| 编译报 `invalid opcode` 或链上执行报 `invalid opcode` | solc EVM 版本太新 | 确认 `compile.js` 里 `evmVersion: "shanghai"` |
| `missing revert data` | 合约自定义错误被 Ganache 吞了 | 正常现象，测试只看「是否 revert」 |
| `Cannot find module '../binaries/uws_...node'` | Ganache 的 WebSocket 原生模块在 Node 24 下没有预编译包 | 正常现象，会自动 fallback，不影响功能 |
| `OSError: [WinError 1314]` | videohash2 默认用 symlink | 传 `do_not_copy=False` |
| `UnicodeEncodeError: 'gbk'` | Windows 控制台编码 | `chcp 65001`；本仓库脚本已强制 UTF-8 |
| `IPFS daemon 没在 ... 上跑` | daemon 没启动 | 另开终端 `ipfs daemon` |
| Remix 刷新后合约/余额消失 | Remix VM 是内存链，刷新即重置 | 演示别刷新；要重复就重新 Deploy |
| `EVIDENCE_ADDRESS` 查询报 NotFound | 地址是刚部署的空合约 / 链重启了 | 重新 `record`，并更新 `$env:EVIDENCE_ADDRESS` |
| `wsl --install` 没反应/报错 | 系统未开虚拟化 | BIOS 开 VT-x / SVM，或 `wsl --update` |
| Fabric 部署链码卡在 npm install | 容器访问 npm 慢 | 链码目录加 `.npmrc` 指 npmmirror（见 Fabric 文档） |
| Fabric invoke 报 `ENDORSEMENT_POLICY_FAILURE` | AND 策略没收集到两个组织的背书 | 命令里加第二个 `--peerAddresses` |
