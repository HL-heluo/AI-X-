# 创作信息存证（MVP）：生成后上 Fabric，作者与平台可查

> 这是当前**主线实现**。相比 `视频溯源实现.md`（旧版，含感知哈希与副本检测），本版删掉了「视频被修改后的同源检测」，只保留一件事：
> **用户在本平台生成视频后，把该视频的创作信息写进 Fabric 链，之后作者和平台都能查到。**
>
> 对应代码：
> - 链码：`chaincode/video-evidence/lib/videoEvidence.js`（v2，已按本设计改写）
> - 本地链码测试（无需 Docker）：`chaincode/video-evidence/test/local-test.js`
> - 跨语言一致性测试：`chaincode/video-evidence/test/from-python-record.js`
> - 记录生成：`python/creation_record.py`
> - 端到端演示：`python/demo_creation.py`
> - 网关：`bridge/server.js`（不用改）

---

## 1. 验收标准（做到这三条就算完成）

1. 视频生成后，链上出现一条记录，能拿到 `txId` 与交易时间；
2. 作者用 `ownerId` 能查到自己全部作品的存证；
3. 平台能列出全部存证，也能按 `videoId` 或文件 `SHA-256` 精确定位单条。

## 2. 边界：做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 证明「某视频在某时间点、由某作者、以某组参数被平台登记」 | ❌ 不做转码副本检测（感知哈希整体删除） |
| 证明「文件字节未被篡改」（SHA-256 精确比对） | ❌ 不做侵权/版权判定 |
| 凭文件哈希反查记录、按作者查作品 | ❌ 不保证「视频确实是 AI 生成的」（链只记平台声明） |

**信任假设（写进报告）**：平台是唯一写入方；Fabric 的 MSP + AND 背保证「写入后不可单方改」，但不保证「写入内容真实」。

## 3. 链上记录（字段）

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `videoId` | string | 平台生成 | 仅 `[A-Za-z0-9._-]`，作主键 `VIDEO_<videoId>` |
| `sha256` | 64 hex | 文件字节 | 完整性 + 反查索引 |
| `ownerId` | string | 平台账号 | **作者（业务用户 ID）**，旧字段 `creator` 仍兼容 |
| `ipfsCid` | string? | IPFS | 可留空，后续补 |
| `generationParams` | string? | 平台 | JSON：model/seed/promptSha256（**prompt 只存哈希**） |
| `providerTaskId` | string? | provider | 用于和 provider 账单对账（可选） |
| `mediaMeta` | string? | ffprobe | JSON：width/height/codec/durationMs/sizeBytes |
| `perceptualHash` | 16 hex? | （已废弃） | 字段保留兼容，MVP 留空 |
| `createdAtTx` / `createdAtEpochMs` | string / number | **链码填** | 交易时间，客户端改不了 |
| `ledgerTxId` | string | **链码填** | 可追溯交易 |
| `recorderOrg` | string | **链码填** | 写入方 MSP（应为 PlatformOrgMSP） |

## 4. 三条索引（链上状态，非中心化数据库）

| 索引 | 用途 |
|---|---|
| 主键 `VIDEO_<videoId>` | 按 ID 读详情 |
| `owner~videoId` | **作者查自己的全部作品** |
| `sha256~videoId` | **拿到文件反查是哪条记录** |

## 5. 链码函数（5 个主函数 + 2 个辅助）

| 函数 | 谁用 | 作用 |
|---|---|---|
| `CreateVideoRecord(recordJson)` | 平台 | 校验 + 幂等 + 写记录 + 建索引 + 事件 |
| `ReadVideoRecord(videoId)` | 作者/平台 | 读详情 |
| `QueryRecordsByOwner(ownerId)` | 作者 | 按作者查全部（`QueryRecordsByCreator` 为兼容别名） |
| `QueryAllRecords(limit)` | 平台 | 按 `VIDEO_` 前缀范围扫全量（默认 100，上限 500） |
| `VerifyExactHash(videoId, sha256)` | 作者/平台 | 完整性校验（返回 JSON，不返回裸布尔） |
| `FindVideoIdsBySha256(sha256)` | 作者/平台 | 凭文件哈希反查 |
| `GetRecordHistory(videoId)` | 审计 | 版本历史 |

> 链码返回值一律是字符串（fabric-shim 限制）；时间取 `getTxTimestamp()`；重复 `videoId` 直接报错，不覆盖。

## 6. 写入流程（5 步）

```
① 生成完成 → 拿到视频文件 + user_id + 模型/seed/prompt
② python/creation_record.py：算 SHA-256、ffprobe 媒体信息、拼 recordJson
③ （可选）上传 IPFS → CID 填进 record
④ bridge POST /invoke {fn:"CreateVideoRecord", args:[recordJson]}
⑤ 平台本地记 evidence 状态（committed + txId）；失败进 pending 重试
```

## 7. 查询流程（3 个视角）

```
作者：QueryRecordsByOwner(ownerId)      → 我有哪些作品、各自何时登记、参数摘要
平台：QueryAllRecords(limit)            → 全量列表（可按需分页）
双方：FindVideoIdsBySha256(sha256)      → 拿到一个文件，反查是哪条记录
      VerifyExactHash(videoId, sha256)  → 逐字节核对是否被改过
```

## 8. 三步跑起来

### 8.1 本地验证链码逻辑（不需要 Docker）

```powershell
cd G:\AIVideo\双链存证\chaincode\video-evidence
npm install            # 首次
npm test               # 10 组用例：写入/读回/按作者查/全量/反查/校验/幂等/参数/历史
```

### 8.2 生成一条记录（不需要 Fabric）

```powershell
cd G:\AIVideo\双链存证
python python\creation_record.py 你的视频.mp4 --video-id vid_demo_001 --owner user_1001 `
  --model jimeng --seed 42 --prompt "一只猫在弹钢琴" --out record.json

# 再把 Python 产出的记录喂给链码，验证跨语言字段一致
node chaincode\video-evidence\test\from-python-record.js record.json
```

### 8.3 上链（需要 Fabric + bridge）

```powershell
# WSL：起网络、部署链码（见 docs/Fabric环境搭建.md）、起 bridge
node bridge/server.js

# Windows：写链 + 三种查询
python python\demo_creation.py 你的视频.mp4 --video-id vid_demo_001 --owner user_1001 `
  --model jimeng --seed 42 --prompt "一只猫在弹钢琴"
```

输出会依次打印：记录 → txId/交易时间 → 作者查询条数 → 平台查询条数 → 完整性校验结果。

> 没有 Fabric 时用 `--dry-run` 只生成记录；bridge 不可用时脚本会明确报错，不会假装成功。

## 9. 与旧设计（视频溯源）的差异

| 旧版 | 本版 |
|---|---|
| SHA-256 + 64 bit 感知哈希 | **只留 SHA-256**（删 videohash2/FFmpeg 依赖） |
| 判「转码副本是否同源」 | **删除**，明确写「不做副本检测」 |
| 创作者是钱包地址 | 创作者是 `ownerId`（业务用户 ID） |
| `VerifyPerceptualHash` | 删除 |
| 反向索引 + 创作者索引 | 保留（作者查作品 + 拿文件反查） |

## 10. 与 AIVideo 后端集成

当前集成和验收步骤见 [《区块链审查与改造交接》](../../区块链审查与改造交接.md) 第 4、5 节。`finish_transferred` 成功落下视频资产时登记待处理存证，独立 worker 调用本机 Fabric 网关。作者从 `GET /assets/{asset_id}/evidence` 查询回执，平台通过受控入口按编号、作者代号或文件指纹回查。

## 11. 局限（报告「局限」一节）

1. **平台是唯一写入方**：链证「写入后不可改」，不证「写入内容真实」；
2. **抢注无法根治**：链只能证明「谁先登记」，缓解是生成即写链 + provider 任务 ID 可对账；
3. **链上时间 ≠ 创作时间**：只证明写入时刻；
4. **文件持久化**：IPFS 必须 pin，否则记录在、文件丢；
5. **不做副本检测**：转码后的副本查不到（明确写为未来工作）；
6. **AND 背书的可用性代价**：审计方离线则写不进。
