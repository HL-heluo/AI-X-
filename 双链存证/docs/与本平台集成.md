# 接进 `G:\AIVideo` 后端：落点清单

> **本页是早期集成草案。** 当前开发按 [《区块链审查与改造交接》](../../区块链审查与改造交接.md) 第 4、5 节执行。Ganache 同步 VCR 积分，本机 Fabric 独立登记视频创作信息；入口为视频资产存证回执。

> 目标：**不破坏现有可用系统**的前提下，把「双链存证」作为一条旁路接进去。
> 原则（按优先级）：
> 1. 不改支付、不改生成主链路的行为；链上失败只记录，不回滚用户已拿到的视频；
> 2. 链上调用是 IO，**绝不能放进 SQLite 的写事务里**（工程文档 §4.2/§9.2 已经为转存踩过这个坑）；
> 3. 契约冻结：**不要改 `TaskOut` 的响应形状**（前端 `json.requireInt` 之类很挑），另开端点。
>
> 本文给的是落点与代码骨架，具体写法要顺着现有代码风格补；标 `（新增）` 的文件是新增，其余是改动点。

## 1. 数据：一张新表就够

`backend/app/models.py`（新增模型）：

```python
class EvidenceRecord(Base):
    """一条视频的链上存证状态。一行 = 一个 task 的存证尝试。"""

    __tablename__ = "evidence_records"

    id: Mapped[int] = mapped_column(primary_key=True)
    task_id: Mapped[int] = mapped_column(
        ForeignKey("tasks.id", ondelete="CASCADE"), nullable=False, unique=True
    )  # UNIQUE(task_id)：补偿任务幂等的第一道闸

    video_id: Mapped[str] = mapped_column(String(64), nullable=False, unique=True)
    # 对外可展示的 videoId（uuid 或 "vid_<task_id>_<rand>"），链上以 keccak256(video_id) 作 key

    asset_id: Mapped[int | None] = mapped_column(Integer, nullable=True)  # 对应 assets.id（视频资产）

    sha256: Mapped[str | None] = mapped_column(String(64), nullable=True)
    perceptual_hash: Mapped[str | None] = mapped_column(String(16), nullable=True)  # 16 位六进制
    ipfs_cid: Mapped[str | None] = mapped_column(String(128), nullable=True)

    # 以太坊侧
    eth_video_id_hash: Mapped[str | None] = mapped_column(String(66), nullable=True)  # 0x + 64
    eth_reserve_tx: Mapped[str | None] = mapped_column(String(66), nullable=True)
    eth_settle_tx: Mapped[str | None] = mapped_column(String(66), nullable=True)
    eth_refund_tx: Mapped[str | None] = mapped_column(String(66), nullable=True)

    # Fabric 侧
    fabric_tx_id: Mapped[str | None] = mapped_column(String(128), nullable=True)
    fabric_committed_at: Mapped[datetime | None] = mapped_column(UtcDateTime, nullable=True)

    status: Mapped[str] = mapped_column(String(24), nullable=False, default="pending")
    """pending / fingerprints_done / ipfs_done / committed / failed / abandoned"""

    attempts: Mapped[int] = mapped_column(Integer, nullable=False, default=0)
    last_error: Mapped[str | None] = mapped_column(Text, nullable=True)
    created_at / updated_at  # 跟现有表的写法保持一致
```

Alembic：`backend/alembic/versions/xxxx_add_evidence_records.py`，照现有迁移文件抄一份结构即可。

## 4. 落点：两个事务 + 一个事务外 IO 相位

照抄现有「转存三段式」的结构（`services/generation.py` 的 `_claim_transfer → perform_transfer → finish_transferred`）：

1. **成功收尾的事务里**（`finish_transferred` 之后，同一事务）：
   ```python
   evidence = evidence.ensure_pending(session, task)   # 只写一行 pending，无 IO
   ```
2. **worker 相位**（`app/worker.py` 的 `run_once` 里加一个 `_sync_evidence(session, moment)`）：
   - 取 `status in ("pending", "failed") and attempts < max` 的行；
   - **先闭事务**，再在事务外读视频文件算指纹/上传（大文件 IO）；
   - 回到短事务里写状态与 txId。

   worker 现在的相位划分见 `run_once`（`_expire_stale` / `_advance_submitted` / `_retry_transfers` / `_dispatch_ready`），
   新相位放在 `_retry_transfers` 之后、`_dispatch_ready` 之前最自然。

3. **资金侧**：`services/credits.py` 的 `freeze / settle_and_refund / refund_frozen_all` 不动，
   在它们成功之后的同一事务里插 `evidence.ensure_pending`；链上 `reserve` 的触发点放在
   `submit()` 之后（v1 影子模式：失败只记 `last_error`，任务照常跑）。

> ⚠️ 不要把 `requests.post` / `web3.send` 放进 `atomic()` 块里：
> SQLite 单写锁会被网络 IO 占住，整个平台的写入都会变慢 —— 这正是现有代码把转存拆成三段的原因。

返回（前端另写一个「存证回执」卡片，不改现有 `Task` 模型）：

```json
{
  "videoId": "vid_1749...",
  "sha256": "e7d0...",
  "perceptualHash": "dcc05c5ce9a9c010",
  "ipfsCid": "bafy...",
  "fabricTxId": "8f3c...",
```

再加一个**给外部验证方**用的只读端点（不用登录、只回 match，不回记录）：

```

→ {"videoId":"...","match":true}
```

> 这个端点对应报告的「验证方无需暴露完整记录」需求，也是答辩演示「验真」最直观的入口。

## 6. 密钥与部署（写进报告的「工程约束」）

- 平台私钥（`SETTLER_ROLE`）**绝不能进 `.env` 提交到仓库**：演示环境用 Ganache 的测试私钥没问题，
  报告里必须写明「生产环境用 KMS/HSM 或节点托管账户，私钥永不落盘」。
- `eth_contract_address` 每次重新 `./network.sh down` / 重启 ganache 都会变，写进 `.env` 而不是硬编码。
- 影子模式跑稳之前，`chain_enabled=False` 进 CI；现有测试（`backend/tests/`）不会因为链不通而红。
